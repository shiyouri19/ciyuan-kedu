# 参考项目研究记录

版本：1.0（基于 2026-10-24 实际抓取的公开资料）
研究方式：仅阅读公开 README 与更新说明，**未引入任何源码、素材或文案**。

## 目的

PotatoVN、The-Order、Animeko（原 Ani）作为产品设计与交互流程参考。本项目不复刻其实现，也不复制其源代码。
参考重点：作品库组织方式、识别与人工确认流程、多数据源边界、错误与空状态处理。

## 记录 1 · The-Order

- **日期**：2026-10-24
- **项目/页面**：https://github.com/Ph-Rank/The-Order （Windows 原生 Galgame 管理器：书架、作品资料、识别与游玩记录）
- **观察到的设计**：
  1. 书架组织：扫描文件夹或手动导入；**同一作品允许多个安装并存**；封面视图 / 列表视图；搜索、筛选、愿望清单。
  2. 识别是一条完整流水线：先读可执行文件版本信息作为**本地证据** → 清洗标题噪声（下载包、限定版、中文包装标签、翻译组标签、构建版本、位数）但**保留版本标记** → 构建候选身份 → 排序 → **只有排序第一名唯一确定时才自动应用**。
  3. 同名作品（homonyms）被显式记录，不做静默合并。
  4. 「移除书架条目不会删除游戏文件」写进功能说明。
  5. 资料语言偏好：缺少中文时自然回退，而不是显示空白。
  6. 允许用户自选封面、保留个人名称 —— 个人数据与外部资料分区。
- **解决的用户问题**：本地文件一堆、分不清哪个是哪个；**自动识别猜错比不识别更烦人**。
- **本项目是否采用**：修改后采用。
- **本项目的具体实现**：
  - 阶段 6 绑定策略：只有「排序第一且无并列、置信度 ≥ 阈值」才写 `bind_state = auto`，其余进 `pending` 等人工确认。**禁止「取最高分自动套用」**。
  - 标题清洗规则：剥离字幕组、分辨率、片源（BDRip/WEB-DL）、语言标记、版本号、编码，**但保留季/期标记**（`S2`、`第2期`、`Season 2`）。
  - 同一标题命中多个作品时，保存候选列表交用户选择，不自动选一个。
  - 归档作品只写 `deleted_at`，绝不触碰本地文件（现有 `archiveAnime` 已符合）。
- **是否涉及代码或素材复用**：否，仅借鉴流程与策略。

## 记录 2 · Animeko（原 Ani）

- **日期**：2026-10-24
- **项目/页面**：https://github.com/open-ani/animeko （Kotlin + Compose Multiplatform，找番/追番/看番/离线缓存/BT/弹幕）
- **观察到的设计**：
  1. 文件名解析踩过的真实坑：`S02`、`1080p` 曾被误判成集数，修复后要求**集数必须独立成段**。
  2. 匹配召回：包含匹配 + 相似度阈值，按相似度排序，并**显式排除续季、剧场版、总集篇**作为干扰项。
  3. 多数据源由 `MediaAutoSelector` 统一调度，支持自动换源与失败重试，数据源是独立模块。
  4. 收藏与进度同步到 Bangumi 账号；条目 / 剧集 / 媒体为三层模型。
  5. datasource 与 UI 彻底分离，Provider 可替换。
- **解决的用户问题**：字幕组命名千奇百怪；跨季混淆（把第二季匹配成第一季）。
- **本项目是否采用**：修改后采用（匹配策略与 Provider 边界）；不采用其播放器、弹幕、BT 部分。
- **本项目的具体实现**：
  - 集数识别要求边界：数字前后必须是分隔符或首尾，且不能紧跟 `S`；`720 / 1080 / 2160` 列入黑名单，不当集数。
  - 匹配时先用「去掉季标记的标题」召回，再用年份与集数范围二次校验。
  - 剧场版 / 总集篇 / OVA 作为负样本：候选标题含这些词而本地文件名不含时降权。
  - Provider 只做**降级切换**（AniList → Bangumi），不做多源结果合并（集数定义不同，合并必错）。
- **是否涉及代码或素材复用**：否。该项目为 AGPLv3，明确不复制任何代码。

## 记录 3 · PotatoVN

- **日期**：2026-10-24
- **项目/页面**：https://github.com/GoldenPotato137/PotatoVN （Visual Novel 管理工具，WinUI3 + MVVM）
- **观察到的设计**：
  1. 自动检索文件夹内的游戏，并**从多个数据库（Bangumi、VNDB）聚合信息**，同时从账户同步游玩状态。
  2. 从压缩包自动解压、识别并加入库。
  3. 统计游玩时间。
  4. 存档通过外部同步盘（OneDrive 等）间接同步，不自己做云服务。
- **解决的用户问题**：批量入库成本高；资料分散在多个站点。
- **本项目是否采用**：部分采用。
- **本项目的具体实现**：
  - 多源：采用「AniList 主 + Bangumi 备」的**主备切换**，不采用多源聚合（集数结构不同）。
  - 压缩包自动解压入库：**当前不采用**。属「入库」范畴，涉及解压路径安全与磁盘占用，留待 P2 单独设计。
  - 时长统计：已在数据层实现（`totalWatchedMinutes`），未知时长不伪造，思路一致。
  - 云同步：不做。备份走本地文件 + 导出 JSON。
- **是否涉及代码或素材复用**：否。

## 记录 4 · anime-grid（动画生涯个人喜好表生成器）

- **日期**：2026-10-24
- **项目/页面**：https://lab.magiconch.com/anime-grid/ ，源码 https://github.com/itorr/anime-grid
- **研究方式**：阅读其 `html/anime-grid.js`（约 550 行），只做行为观察。
- **观察到的设计**：
  1. **前端不直连 Bangumi**，而是请求作者自建的中间层 `https://bgm-w.magiconch.com/`，接口为 `GET /animes?keyword=` 与 `GET /anime/onlines?keyword=`。原因很明确：浏览器 `fetch` 无法设置 Bangumi 要求的 `User-Agent`，跨域也受限，封面还有防盗链。
  2. **搜索是回车触发，不是实时联想**：输入框 placeholder 写的是「输入关键词、回车查找动画」，请求在 `form.onsubmit` 里才发出。搜索框打开时先用预置缓存渲染一份默认列表，避免空白。
  3. **内存缓存**：`Caches[url]` 按完整 URL 缓存 JSON，永不过期；封面按 id 直接拼 URL。
  4. **只存 id 或纯文本**：选中结果记 Bangumi id；搜不到时可点「用搜索框里的文字」，此时存字符串。数据结构极简，不缓存完整元数据。
  5. **封面经中间层代理加载，并加 `crossOrigin="Anonymous"`** —— 因为最终要用 canvas 合成图片，跨域图会污染画布。
- **解决的用户问题**：不想打完整番名；不想在多个站点之间来回跳。
- **本项目是否采用**：**部分采用，其中两点做得更好**。
- **本项目的具体实现**：
  - **中间层天然存在**：我们本来就有本地 Node 服务，正好承担 `bgm-w` 的角色，且无需部署公网。Bangumi 的 UA 与跨域问题在服务端直接绕开。
  - **改为实时联想**：输入 ≥ 2 个字符、防抖 300ms 自动查；回车则立即查并跳过防抖。比原站少一次「按回车」。
  - **打开即给候选**：先展示本地库已匹配的作品，再展示缓存过的热门条目，不留空白。
  - **缓存落盘到 SQLite 并带 TTL**（内存缓存重启即失效，也无法跨查询复用）。
  - **封面下载到 `cache/covers/`，经同源 `/cover/:id` 返回**：离线可用，且将来做总结图时 canvas 不会被污染。
  - **点选后拉详情、自动建季与集**，只把 `external_id` 写入 `subject_external`。
- **是否涉及代码或素材复用**：**否，一行未取**。该项目未标注开源协议，README 注明「禁止商业、盈利相关利用」，故只做行为层面的观察，不做代码移植。

## 对后续阶段的直接影响（结论）

| 影响点 | 落点 | 具体要求 |
|---|---|---|
| 自动绑定必须有「唯一性」判据 | 阶段 6 | 并列或低置信一律进 pending，禁止取最高分 |
| 集数解析必须独立成段 | 阶段 6 | 数字前后需分隔符，排除 Sxx 与 720/1080/2160 |
| 标题清洗保留季标记 | 阶段 6 | 剥离字幕组/分辨率/编码，保留 S2、第2期 |
| 同名作品留候选 | 阶段 6 | 保存候选列表，不静默合并 |
| Provider 只降级不合并 | 阶段 5 | AniList 主、Bangumi 备，失败切换并提示 |
| 归档不动本地文件 | 阶段 2 起 | 已有软删除实现，后续不得破坏 |
| **搜索走服务端中间层** | 阶段 3 | 前端不直连外部 API；UA、跨域、防盗链都在这层解决 |
| **封面必须同源返回** | 阶段 3 / 4 | 下载到 `cache/covers/`，经 `/cover/:id` 提供，为离线与 canvas 合成做准备 |
| **搜索联想改实时** | 阶段 3 | 防抖 300ms + 回车立即搜 + 打开即有候选 |
