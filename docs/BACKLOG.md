## B-001 搜索联想录入（用户最关心的一条）

- **状态：已完成（2026-10-24）** —— 实时联想、双源搜索、封面代理、点选自动填表、自动标签均已上线。
- **提出**：2026-10-24
- **原始描述**：「我在点击格子之后，可以在搜索框里搜索关键词，相关的动画会弹出来，不用我自己填完整的名字」（参考 https://lab.magiconch.com/anime-grid/ 的交互）
- **我的理解**：新增作品时，输入几个字就出候选列表，点一下选中并自动带出标题、年份、集数、封面。**不用打完整番名。** 对应方案里 P0 的「极速录入」：≤3 秒加一部，必填项只有关键词。
- **现状差距**：阶段 2 只有纯手动输入，必须打全名，没有候选。
- **依赖**：
  1. 元数据 Provider（AniList / Bangumi）
  2. **HTTP 代理支持**（`net.js` 尚未编写；Node 的 fetch 不读 `HTTP_PROXY`，必须显式实现 CONNECT 隧道）
  3. 搜索缓存（避免每次输入都打网络）
- **阶段**：原计划在阶段 5。**建议提前**，见下方「实测结论」。

### 实测结论（2026-10-24，决定 Provider 分工）

对 AniList 用中文关键词测试（`Page.media(search:)`）：

| 关键词 | 命中 | 结果 |
|---|---|---|
| 芙莉莲 | **0** | 搜不到《葬送的芙莉莲》 |
| 葬送的芙莉莲 | **0** | 全名也搜不到 |
| 迷宫饭 | 1 | ダンジョン飯 |
| 孤独摇滚 | 1 | ぼっち・ざ・ろっく！ |
| 进击的巨人 | 1 | 進撃の巨人 |
| 药屋少女 | 1 | 薬屋のひとりごと |

**AniList 对中文关键词的检索不可靠**（6 个样本里 2 个零命中，恰恰是最常见的口语简称）。它对 `search` 的索引偏日文原名与罗马字，中文别名不在检索范围内。

反观 Bangumi：早前实测 `葬送的芙莉莲` 直接命中 400602，中文检索明显更好，但**必须走代理**。

### 由此确定的 Provider 分工（不推翻主源决定）

- **元数据主源仍是 AniList**（用户 2026-10-24 决定），负责拉详情、集数、年份、封面。
- **搜索联想以 Bangumi 优先**，AniList 作为兜底（日文名/英文名关键词、或代理不可用时）。
- **两个源的候选列表可以合并展示**，但这是合并「候选」，不是合并同一部作品的字段——用户选中哪个源，就只从那个源拉详情并记录 `external_id`。这样不会出现集数定义冲突（`REFERENCE_RESEARCH.md` 反对的是后一种合并）。

## B-006 接入 Dandanplay 作为中文直连搜索源

- **提出**：2026-10-25
- **动机**：`api.bgm.tv` 在大陆直连不通，虽然开代理或配中转都能解决，但 Dandanplay 国内可直连、中文数据好、且返回**番剧 + 剧集列表**，正好补上「选中后集数存不下来」的缺口。
- **状态**：等待用户申请开发者凭据（AppId / AppSecret）
- **申请信息**：项目地址填 `https://github.com/shiyouri19/ciyuan-kedu`，项目类型选「开源项目（非商业）」，平台只勾 Windows + Web（无 Android 端）

### 认证方式（2026-10-25 查官方文档核实）

**签名验证模式**（客户端应用必须用这个，推荐）：

| 请求头 | 值 |
|---|---|
| `X-AppId` | 应用 ID |
| `X-Timestamp` | UTC 秒级 Unix 时间戳 |
| `X-Signature` | `base64(sha256(AppId + Timestamp + Path + AppSecret))` |

- 拼接顺序 `AppId → Timestamp → Path → AppSecret`，无分隔符，区分大小写
- `Path` 形如 `/api/v2/search/episodes`，**不含域名、不含 `?` 之后的查询参数**
- 另有「凭证模式」（`X-AppId` + `X-AppSecret`），仅适用于能保护密钥的服务端，**本项目不用**

**易错点（曾写错）**：不是 `X-AppSignature`，是 `X-Signature`；且 `X-Timestamp` 是必填，漏了会返回 `403 Missing Authentication Headers`。

### 接口分类

| 类型 | 例子 | 认证要求 |
|---|---|---|
| 公开接口 | 文件识别、搜索、获取弹幕 | 只需**应用级**认证（签名），不需要用户登录 |
| 受限接口 | 关注、播放历史、发弹幕 | 还需用户 JWT，**当前暂不开放** |

新申请的应用默认只能访问公开接口。本项目只用检索类公开接口。

### 必须遵守的约束

1. **AppSecret 不得硬编码、不得进仓库**。由用户填入本机 `config.json`（已 gitignore），仓库只留 `config.example.json` 占位。
2. **必须缓存**。官方建议按 ID/关键词缓存 2–6 小时；热门新番当天 0.5–1 小时，老番 2–7 天。搜索类接口有调用量检测，超常会被限流。
3. 不得批量抓取、不得下载弹幕库、不得用于商业目的。
4. 2026-06-25 起启用应用分层与额度管理，需关注所用层级。
