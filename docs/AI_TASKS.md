# AI 编程助手分阶段任务书
版本：0.1

## 0. 协作规则（每次任务都必须遵守）

**强制前置：** 每轮开始先阅读并遵守 `AGENT_RULES.md`。如果该文件与本任务提示冲突，以 `AGENT_RULES.md` 为准，除非用户明确授权例外。参考项目研究遵守 `REFERENCE_RESEARCH.md`。

将以下规则放在 AI 编程助手的项目指令中：

> 你正在实现一个 Windows 优先、本地优先的个人番剧管理软件。请先阅读 `docs/PRD.md`、`docs/ARCHITECTURE.md`、`docs/DATA_MODEL.md` 和 `docs/ACCEPTANCE.md`。
>
> 一次只实现当前指定任务，不要顺手扩展到后续阶段。优先保持项目可运行、可构建、可测试。不要未经确认更换技术栈、引入大型依赖或重写已完成模块。
>
> 任何数据库变更都必须通过带版本号的迁移实现，并提供测试。核心业务逻辑与 UI 分离；不要在 React 组件中直接拼 SQL 或调用外部 API。所有写入要处理错误，关键多步写入使用事务。
>
> 外部作品资料不得覆盖用户个人观看状态、观看日期、评分、标签、备注和收藏。打开本地视频不自动标记已看。文件丢失不能删除作品和观看记录。观看统计按首次观看日期归类，未知时长不得伪造。
>
> 每个任务完成后，运行相关 lint、测试和构建命令，修复本次引入的问题，并更新 README/文档。最终回复必须包含：改动摘要、关键文件、运行过的命令及结果、尚存问题、手工验收步骤。若遇到不明确的产品决策，先列出问题，不要擅自作重大决定。相同失败原因最多进行 3 轮实质不同的修复尝试；达到上限后停止并报告，不得循环重试。完成当前阶段后停止，等待用户指示，不要自动进入下一阶段。

## 1. 阶段 0：项目骨架与工程验证

### 目标
建立最小可运行的 Tauri 2 + React + TypeScript + Vite 工程，确认 Windows 开发和构建环境正常。

### 任务提示词
> 阅读架构文档，初始化最小工程骨架。实现主窗口、基础导航和统一错误展示占位。建立 lint、格式化、测试和构建脚本。不要实现业务功能，不要提前添加云同步或手机端。更新 README，写明依赖、启动、测试和构建命令。完成后实际运行这些命令并报告结果。

### 验收
- 应用可启动。
- 前端与 Tauri 端均可构建。
- 基础测试通过。
- Git 工作区变更清晰，无无关文件。

## 2. 阶段 1：SQLite、迁移与基础仓储

### 目标
建立数据库访问层和首批迁移。

### 任务提示词
> 根据 `DATA_MODEL.md` 实现第一批数据库表和迁移。先实现 `anime`、`user_anime_state`、`seasons`、`episodes`、`episode_watch_state`、`tags`、`anime_tags`、`app_settings`。使用稳定全局 ID、外键、必要索引和参数化查询。实现 repository 层与测试数据工厂。为迁移成功、重复初始化、事务回滚、外键约束和应用重启持久化编写测试。不要实现外部 API、本地扫描或同步。

### 验收
- 初始化和迁移可重复安全执行。
- 核心 CRUD 测试通过。
- 重复记录和非法外键被约束。
- 应用重启后数据保留。

## 3. 阶段 2：番剧库与作品详情

### 目标
完成最基本的个人作品管理。

### 任务提示词
> 实现番剧库页面和作品详情页面。支持手动新增、编辑、查看、归档作品；支持个人状态、评分、收藏、标签、备注；支持搜索、筛选和排序。UI 通过 service/use-case 调用 repository，不直接访问数据库。完善空状态、加载状态、表单校验、删除确认和错误提示。补齐组件/服务测试与手工验收说明。不要接外部元数据源。

### 验收
参考 `ACCEPTANCE.md` 第 2 节。

## 4. 阶段 3：集数与手动观看记录

### 目标
完成项目最核心的观看记录功能。

### 任务提示词
> 实现季/集管理和手动观看记录。用户可以单集标记已看/未看、批量标记连续范围、整季标记，并可指定首次观看日期或选择日期不详。批量操作需显示影响范围；重复标记不能重复计数；取消已看时按数据模型清除当前状态日期，并支持再次修正。实现观看记录 service、事务和测试。打开文件与观看状态无关；当前不实现本地播放器。请提供边界测试：空季、特殊集、未知时长、日期不详、跨年日期、批量部分失败和重复点击。

### 验收
参考 `ACCEPTANCE.md` 第 3 节。

## 5. 阶段 4：统计与数据可视化

### 目标
展示准确、可解释的观看统计。

### 任务提示词
> 实现统计服务和统计页面。统计已看集数、累计标准时长、年度/季度集数和时长。按每集首次观看日期归类，而非记录创建时间。未知时长只计入集数，不估算时长；日期不详单独展示。统计规则必须写成独立、可测试的纯函数或服务。UI 明确说明时长是标准时长估算，不是实际播放时长。为跨年、季度边界、无日期和无时长场景编写测试。

### 验收
参考 `ACCEPTANCE.md` 第 4 节。

## 6. 阶段 5：多源元数据

### 目标
接入至少两个独立元数据 Provider，并保留手动编辑能力。

### 任务提示词
> 设计统一 Metadata Provider 接口，先接入 Bangumi 和 AniList（先验证当前 API 的可用性、认证要求、限流和许可条件）。实现搜索、详情获取、数据归一化、缓存和错误映射。搜索结果需由用户选择后再导入。保存外部 ID 与来源信息。实现字段冲突规则：手工锁定字段优先，个人状态/评分/标签/备注/观看历史永不被 Provider 覆盖。网络失败时显示缓存和本地条目。为无结果、断网、限流、字段缺失和重复外部 ID 编写测试。不要让某一个 Provider 成为应用启动依赖。

### 验收
参考 `ACCEPTANCE.md` 第 5 节。

## 7. 阶段 6：本地媒体扫描与关联

### 目标
建立本地文件索引和人工确认式匹配。

### 任务提示词
> 实现媒体根目录配置、文件扫描、文件名解析候选、待匹配列表、集数关联、多版本管理和文件丢失状态。扫描过程必须是非破坏性的，不得删除作品、集数或观看记录。解析不确定时展示候选让用户确认，禁止自动把低置信度结果静默关联。实现扫描进度、取消、错误记录和重新扫描。补齐路径移动、重复文件、无匹配文件、特殊集和多版本测试。

### 验收
参考 `ACCEPTANCE.md` 第 6 节。

## 8. 阶段 7：调用默认播放器

### 目标
从集数列表打开关联视频。

### 任务提示词
> 实现“打开文件”命令，通过 Tauri/Rust 的安全本机能力调用 Windows 默认关联程序。使用安全参数传递方式，不拼接 shell 命令。打开失败时向 UI 返回可理解的错误。绝不因打开文件而自动标记已看。为文件不存在、路径无效、权限不足和正常打开流程提供测试或手工验收说明。

### 验收
参考 `ACCEPTANCE.md` 第 6 节中播放器相关项目。

## 9. 阶段 8：资源发现中心

### 目标
先实现站点搜索链接模板，再按需要增加 RSS/API。

### 任务提示词
> 实现资源站点配置管理。首版支持站点名称、基础 URL、搜索 URL 模板、启用状态和备注；模板应能将番剧标题安全 URL 编码。用户可预览并通过系统浏览器打开链接。站点配置错误和单站失败不能影响其他功能。不要绕过登录、验证码、访问控制或站点规则。将 Provider 接口设计为未来可扩展 RSS/API，但当前不必实现所有站点的抓取。

### 验收
参考 `ACCEPTANCE.md` 第 7 节。

## 10. 阶段 9：备份、恢复与发布准备

### 目标
使软件具备可靠的数据保护和可交付能力。

### 任务提示词
> 实现数据库备份、备份校验、恢复前确认、恢复前自动备份当前数据库、失败回滚或清晰恢复指引。补充导出/导入个人数据能力，定义重复作品与外部 ID 冲突策略。完善安装包构建、README、版本号、已知问题、干净环境安装和发布验收。运行全部测试并逐项核对 `ACCEPTANCE.md`。不要在发布准备中加入云同步或手机端功能。

### 验收
参考 `ACCEPTANCE.md` 第 8、9 节。

## 11. 每阶段结束时的固定报告格式

要求 AI 编程助手按以下格式回复：

1. **完成内容**
2. **关键文件与模块**
3. **数据库迁移**
4. **测试与构建命令及结果**
5. **手工验收步骤**
6. **已知问题/未完成项**
7. **建议 Git commit 信息**
