# 产品需求文档（PRD）

版本：0.1  
状态：开发基线草案  
产品代号：AniShelf（暂定，可更名）

## 1. 产品概述

AniShelf 是一款 Windows 优先、本地优先的个人番剧管理软件。它以个人收藏和观看记录为核心，逐步整合外部作品资料、本地动画文件与 BT 资源搜索入口。

核心目标是：即使断网、没有本地视频，用户仍能管理番剧、补记观看进度、维护个人评分和标签，并查看可靠的观看统计。

## 2. 产品原则

1. **个人数据优先**：观看状态、观看日期、评分、标签、备注和用户手工修改均由用户控制。
2. **本地优先**：核心数据保存在本机，离线时核心功能可用，不强制登录。
3. **功能分层**：作品管理、观看记录、本地文件、外部元数据、资源入口分别建模。
4. **可恢复**：提供数据库备份与恢复能力，避免一次错误操作导致数据不可恢复。
5. **渐进开发**：先实现可用的个人番剧库，再加入外部资料、本地媒体和资源搜索。
6. **为未来同步留接口，但不提前实现**：当前不做手机端、账号、云端服务和自动同步。

## 3. 目标用户与主要场景

### 3.1 目标用户

希望在电脑上统一管理番剧收藏、观看进度、个人评价、本地视频文件和资源搜索入口的个人用户。

### 3.2 典型场景

- 添加一部番剧到想看列表。
- 将某部番剧设为在看、已看完、暂停或弃番。
- 在手机或其他播放器看完后，回到软件手动补记一集、数集或整季。
- 修正误标的观看记录。
- 查看某部番剧看到了第几集。
- 按首次观看日期统计某年或某季度看过的集数和标准时长。
- 扫描本地媒体目录，将视频匹配到作品和集数。
- 从软件中打开本地视频，交给 Windows 默认播放器。
- 搜索外部作品资料；当网络不可用时仍可查看缓存和本地资料。
- 从用户配置的 BT 站点搜索资源，必要时跳转原站。
- 备份数据库，在重装系统或更换电脑前保存个人数据。

## 4. 当前版本范围

### P0：首个可用版本必须具备

- 番剧条目新增、编辑、查看和删除/归档。
- 番剧库列表、搜索、筛选和排序。
- 个人观看状态：想看、在看、已看完、暂停、弃番。
- 个人评分、标签、备注和收藏标记。
- 季与集的基本管理。
- 单集已看/未看手动切换。
- 批量标记连续集数、指定范围或整季。
- 首次观看日期可编辑；支持“日期不详”。
- 撤销或修正误标操作。
- 以已看集数 × 标准单集时长计算累计观看时长。
- 年度、季度统计按每集首次观看日期归类。
- SQLite 持久化、数据库迁移、备份与恢复。
- 基本错误提示、空状态、加载状态和操作确认。

### P1：核心体验增强

- Bangumi 与 AniList 元数据搜索/导入。
- 外部 ID 与数据来源记录。
- 元数据缓存、失败降级、手动修正。
- 本地媒体目录扫描。
- 文件名解析和作品/集数匹配建议。
- 文件与集数关联、多版本管理、文件丢失状态。
- 点击集数后调用 Windows 默认关联播放器。
- 资源发现中心：每个站点至少支持配置搜索 URL 模板。
- 站点启用/停用、测试链接和状态提示。
- 简单的数据导入/导出能力。

### P2：可后续迭代

- 支持 RSS/API 的站点展示资源列表。
- 更完善的字幕、分辨率、编码、版本识别。
- 更多元数据源 Provider。
- 高级统计、趋势图和自定义报表。
- 可选指定外部播放器。
- 手机端和跨设备同步（未来独立项目阶段）。

## 5. 明确不做的事情

当前版本不实现：

- 内置视频播放器。
- 实际播放时长或播放进度追踪。
- 自动把“打开视频”视为“已看完”。
- 手机端、云端账号和自动同步。
- 自动下载或绕过站点登录、验证码、访问控制。
- 以外部元数据覆盖用户个人状态。
- 未经确认的后台联网、自动更新或上传个人数据。

## 6. 核心功能需求

### FR-01 番剧库

- 可新增本地番剧条目，也可从外部资料源导入。
- 每个条目有稳定的内部 ID。
- 支持标题、别名、年份、作品类型、简介、封面等基本资料。
- 支持关键词搜索、状态筛选和常用排序。
- 外部资料缺失时，用户仍可手动建立完整条目。

### FR-02 个人状态

- 状态包括：想看、在看、已看完、暂停、弃番。
- 评分、标签、备注、收藏均属于个人数据。
- 作品资料更新不得重置个人状态。
- 状态与单集观看记录可以存在不完全一致的情况；软件可提示用户，但不应擅自覆盖。

### FR-03 集数与观看记录

- 一部作品可包含多个季；每季可包含正片集数及特殊内容。
- 每集至少有内部 ID、集数标识、标题（可空）、标准时长（可空）。
- 用户可单集切换已看状态。
- 用户可选择起止集批量标记，也可整季标记。
- 批量操作前清楚显示影响范围；误操作可撤销或逐集修正。
- 每集记录 `first_watched_at`（首次观看日期）与系统记录的创建/修改时间。
- 日期可只精确到日；允许空值代表不详。
- 用户补记历史观看时，可以指定实际观看日期，不必使用当前日期。
- 重复标记已看不得重复增加观看时长或重复计算集数。

### FR-04 观看统计

- 标准时长优先级：集级手工值 > 季/作品配置值 > 元数据源建议值 > 未知。
- 如果单集时长未知，该集计入集数，但不应伪造时长。
- 累计标准时长 = 已看且有有效标准时长的集数时长之和。
- 年度/季度统计按 `first_watched_at` 的本地日期归类。
- 日期不详的记录放入“日期不详”分类，不纳入某个具体年度/季度。
- 统计页面说明时长为估算标准时长，不是实际播放时长。

### FR-05 外部元数据

- 每个 Provider 独立实现搜索、详情获取、错误映射和速率限制策略。
- Provider 的外部 ID、最后同步时间、字段来源和错误状态应可追踪。
- 合并资料时优先保留用户锁定/手动修改的字段。
- 网络失败时显示本地缓存，并允许手动创建/编辑。
- 一个来源不可用不能阻断软件启动或本地功能。
- 不应将 Provider 的不稳定性暴露为整个应用不可用。

### FR-06 本地媒体

- 用户可添加一个或多个媒体根目录。
- 扫描操作不能删除番剧条目或观看历史。
- 文件移动、改名或丢失时，记录其状态并允许重新定位。
- 一个集可以关联多个版本文件。
- 点击文件应调用系统默认关联程序；启动失败时显示可理解的错误。
- 打开文件不自动标记已看。
- 扫描和文件名解析必须允许人工确认/纠正匹配结果。

### FR-07 资源发现

- 用户可以配置站点名称、搜索 URL 模板、启用状态及备注。
- 模板应安全地编码查询关键词，避免生成无效链接。
- 资源搜索默认通过外部浏览器打开，不绕过站点访问控制。
- 对支持公开 RSS/API 的站点，可在后续阶段增加站内结果列表。
- 站点异常时显示失败状态，不影响其他站点和个人番剧库。
- 用户可自行管理站点配置；不要硬编码单一站点作为唯一来源。

### FR-08 备份与恢复

- 用户可主动创建备份。
- 恢复前提示将替换或合并哪些数据；默认先备份当前数据库。
- 备份格式与数据库版本关联。
- 应有恢复失败的回滚或明确的恢复指引。
- 个人数据可导出为便于迁移的格式；导入时检测重复和冲突。

## 7. 关键用户流程

### 流程 A：手动补记观看

1. 搜索并打开番剧详情。
2. 进入季/集列表。
3. 单击某集的已看开关，或选择批量范围。
4. 如需补记历史，指定首次观看日期；可选“日期不详”。
5. 确认批量操作后更新观看状态与统计。
6. 在详情页或统计页查看更新结果。

### 流程 B：导入作品资料

1. 输入标题或外部 ID。
2. 选择一个或多个资料源进行搜索。
3. 用户确认正确条目。
4. 显示将导入的字段与冲突字段。
5. 导入作品资料，但不覆盖个人状态、评分、标签、备注和观看历史。

### 流程 C：本地媒体匹配

1. 用户添加媒体根目录。
2. 扫描文件并解析可能的标题、季、集、版本。
3. 展示匹配候选与置信度。
4. 用户确认或修正。
5. 保存文件关联；后续文件缺失不影响作品和观看历史。

## 8. 非功能要求

- Windows 10/11 优先；版本支持以实际 Tauri 依赖与构建环境验证为准。
- 首次启动不要求联网。
- 本地核心操作不依赖外部 API。
- 关键写入应使用数据库事务。
- 不允许 SQL 拼接用户输入；使用参数化查询。
- 错误提示需说明用户能采取的下一步。
- 界面避免在大量集数时卡顿；列表应采用合理的分页/虚拟化策略。
- 数据库迁移必须有版本号和测试。
- 不应在日志中记录敏感本地路径之外的个人内容；路径日志需谨慎处理。
- 默认不上传本地文件列表、观看记录或个人数据。

## 9. 成功标准

- 用户可以不联网地创建作品、标记观看和查看基本统计。
- 重启后个人数据完整保留。
- 批量标记与撤销不会造成重复统计。
- 外部元数据源不可用时，核心功能仍可使用。
- 本地文件丢失不会删除作品或观看记录。
- 用户可以备份并恢复个人数据。
- 项目每个阶段均可独立构建和测试。
