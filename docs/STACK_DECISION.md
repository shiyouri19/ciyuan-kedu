## 背景

`docs/AGENT_RULES.md` 第 4 节规定：「未经用户明确同意，不得更换 Tauri 2 + React + TypeScript + Vite + SQLite 的技术基线」。

项目实际实现为 Node.js 本地服务方案，属于对上述基线的偏离。本文件记录偏离的事实、范围与理由，避免后续会话误判。

## 偏离内容

| 项目 | 文档基线 | 实际实现 |
|---|---|---|
| 桌面外壳 | Tauri 2 | 本地 HTTP 服务 + 浏览器（后续可套 Electron） |
| 前端框架 | React + TypeScript + Vite | 原生 HTML / CSS / JS，无构建 |
| 数据层 | Tauri 侧 SQLite 插件 | `node:sqlite`（Node 内置） |
| 测试 | Vitest + cargo test | `node:test` |
| 运行时依赖 | npm 依赖树 | 零第三方依赖，无 `node_modules` |

## 理由

1. 开发机未安装 Rust / cargo。补齐 Tauri 工具链需下载 Rust + MSVC Build Tools，约 1.5–2 GB，耗时约 30–60 分钟。
2. 用户在确认过程中询问「需装 Rust + MSVC，你是要在那安装？」，倾向不安装。
3. 项目目标是个人自用的本地工具，不需要 Tauri 的打包体积优势。

## 切回 Tauri 的代价（评估）

- 需先安装 Rust 工具链与 MSVC Build Tools。
- 前端从原生 HTML 迁到 Vite + React，页面需重写（但当前只有骨架页）。
- 数据层：`node:sqlite` API 需替换为 Tauri SQL 插件或 `rusqlite`，SQL 语句与迁移文件可原样复用。
- 测试用例的断言逻辑可复用，运行方式需改。
- **repository 层的业务语义（幂等标记、日期修正、统计口径）与外壳无关，可完整保留。**

## 附：方案对比（供决策）

### 先澄清层次

两个方案**不在同一层**，不是二选一的关系：

| 层 | 是否有选择 |
|---|---|
| 数据层 | SQLite 单文件，两种方案完全一致，**没有区别** |
| 业务层（repository / 规则） | 语义一致，只是语言不同（JS vs Rust/TS） |
| **外壳层** | **真正的差异全在这里** |

所以“换技术栈”的真实含义是：**换外壳以及随之而来的开发方式**，不是换数据模型。

### 硬数据对比

| 维度 | Node + Electron | Tauri 2 |
|---|---|---|
| 前置环境 | 只需 Node 22（已具备） | 需 Rust 工具链 + MSVC Build Tools |
| 环境下载量 | 0 | 约 3–5 GB |
| 环境配置耗时 | 0 | 约 30–60 分钟（含排错） |
| 安装包体积 | 约 80–120 MB | 约 3–10 MB |
| 解压后占用 | 约 200–300 MB | 约 10–30 MB |
| 空闲内存 | 约 150–250 MB | 约 50–100 MB |
| 冷启动 | 1–3 秒 | 0.3–1 秒 |
| 首次构建 | 无构建步骤 | 5–20 分钟（编译依赖） |
| 改代码后生效 | 保存即生效 | 改前端快；**改 Rust 侧需重新编译 1–3 分钟** |
| 分发方式 | electron-builder 打 NSIS | 自带 bundler |
| 打包时的额外依赖 | 需下载 winCodeSign 等二进制（国内需镜像） | 已包含在工具链内 |
| 生态资料量 | 极大 | 中等，Tauri 2 相对新 |
| 原生窗口手感 | 好 | 最好（用系统 WebView2） |

### 对本项目的真实影响（逐条）

| 需求 | Node 方案 | Tauri 方案 | 差异是否重要 |
|---|---|---|---|
| 扫描目录、读文件属性 | `fs.readdir` + `stat`，几千文件几百毫秒 | Rust 更快 | **不重要**，瓶颈在磁盘不在语言 |
| 文件名解析 | 纯字符串处理 | 纯字符串处理 | 不重要 |
| 调用播放器打开文件 | `child_process` | `std::process::Command` | 不重要 |
| **检测播放器窗口标题（阶段 7）** | 需 `node-window-manager` 之类**含原生模块**的包（会触发编译），或改调 PowerShell（每次 1–2 秒，可 5 秒轮询） | `windows` crate 直接调 User32，干净可靠 | **重要**，这是 Node 方案唯一的编译风险点 |
| 托盘、开机自启 | Electron 内置 | Tauri 内置 | 不重要 |
| 断网可用 | 是 | 是 | 不重要 |
| 数据安全 | 取决于代码 | 取决于代码 | 不重要 |

### 一个被低估的因素：AI 协作效率

本项目的开发方式是人机协作、由 AI 主导编码，这一条比体积和内存重要得多：

- **JS/Node 的训练语料远多于 Rust**，同样一句需求，AI 一次写对的概率更高。
- **Rust 的借用检查器报错**经常需要多轮才能修好，而 `AGENT_RULES` 规定同一失败原因最多 3 轮实质修复。Rust 编译错误极易触到这个上限，导致频繁中断等待人工决策。
- **编译等待**会打断“改一点—验证一点”的小步循环，而小步验证正是这套工作规则的核心。
- 反过来，Node 的“保存即生效”让每次验证几乎是零成本。

### 迁移成本：现在 vs 以后

| 时间点 | 切到 Tauri 的成本 |
|---|---|
| **现在** | 低。前端只有骨架页，数据层刚写完，SQL 与测试断言逻辑可平移，实际重写量约 1–2 天 |
| 阶段 3 之后 | 中。业务规则已成型，需要逐条翻译成 Rust/TS 并重写测试 |
| 阶段 6 之后 | 高。文件扫描、识别流水线是重灾区 |

结论：**越晚切越贵**，所以这个决定现在做是对的。

### 三种落地形态（都属于 Node 路线）

| 形态 | 成本 | 效果 |
|---|---|---|
| 浏览器标签页（现状） | 0 | 像个网页，任务栏里是浏览器 |
| **Edge「安装为应用」** | 约 5 分钟 | 独立窗口、开始菜单/任务栏图标、无地址栏；底层仍是浏览器 |
| Electron 套壳 | 约 1–2 天 | 真正的独立程序，可托盘、开机自启、打包 exe |

### 推荐

**采用 Node 路线，外壳按「先 Edge 安装为应用 → 最后 Electron 套壳」推进。**

支持理由：
1. 体积与内存优势在个人自用场景无实际意义（磁盘以 TB 计、内存 16 GB 以上）。
2. 唯一的硬需求缺口是窗口标题检测，有 PowerShell 兜底方案，不构成阻塞。
3. AI 协作效率的差距是**持续性**成本，而环境配置只是**一次性**成本。

### 什么情况下应该推翻上述推荐、改选 Tauri

只要符合以下任意一条，Tauri 就是更优解，请直接要求切换：

1. 你要求安装包必须小于 20 MB（例如要分发给别人、走便携 U 盘）。
2. 你要求常驻内存低于 100 MB（低配机器、多开场景）。
3. 你打算做深度 Win32 集成（全局热键、窗口钩子、文件关联、系统级悬浮窗）。
4. 你本人愿意学 Rust，并希望借此机会掌握它。

若四条都不符合，Node 路线更划算。
